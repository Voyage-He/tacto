# iOS 后台续播验证

针对「歌曲结束后停住，回到前台才开始下一首」的问题，不能只依赖模拟的播放完成消息或 Dart 单元测试。

## 当前处理

- 播放当前歌曲时，预先读取下一首的元数据和音频，复用正常的本地缓存；只准备一首，不改变当前曲目或队列位置。
- 预缓存失败不打断当前播放，也不保留失败的 Future；真正切歌时可以重新请求。
- 距离结束约五秒时申请有时限的 iOS 后台任务，避免等静音间隙出现、Dart 已被挂起后才申请。暂停、跳转、停止与换曲完成会释放任务。
- iOS 原生 `AVPlayerItemDidPlayToEndTime` 通知再提供一层保护，不依赖 Dart 已经收到结束消息；原有 Dart 回调保留作为补充。

## 原生回归入口

`tool/background_playback_probe.dart` 使用真正的播放器、音频会话、`audio_service`、唱片机页面、Hive 缓存及歌曲数据提供者。诊断音频是本地生成的四十五秒 AAC 正弦音，不使用账号或个人歌曲；网络层以有延迟的测试响应提供元数据和音频。数据保存在独立的 `native-playback-probe` 目录。

先启动一个 iOS 模拟器，然后运行：

```sh
python3 scripts/test_ios_background_playback.py <模拟器 UDID>
```

脚本会构建、安装诊断入口，在第一首开始后立即切到系统设置，使播放器真正进入后台；不连接 Flutter 调试器。它检查：

1. 三首歌曲在超过两分钟的后台运行中自然结束，依次播放后在队列末尾停止。
2. Dart 收到完成消息前，歌曲尾段申请的原生后台任务已经存在。
3. 实际 `MPNowPlayingInfoCenter` 中的歌名依次更新，系统下一首指令保持可用。
4. 下一首的音频在当前歌曲结束前已准备完成。

结果包含模拟器内 JSONL 轨迹的路径。诊断入口会替换模拟器中的 Debug 应用程序；验证后重新构建正常入口以恢复播放器：

```sh
.fvm/flutter_sdk/bin/flutter build ios --simulator --debug --no-pub --target lib/main.dart
```

这套脚本用于开发回归验证。用户已确认后台续播恢复正常；应用内的临时诊断入口、阶段记录与导出接口已移除，更新后首次启动会清除旧版保存的诊断记录。原生后台保护、提前缓存与开发回归脚本继续保留。
